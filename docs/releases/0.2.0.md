# Code Workbench 0.2.0 — Public Alpha

> **Write CAD in Python. Keep the rest of FreeCAD.**

Code Workbench brings [build123d](https://github.com/gumyr/build123d) and
[CadQuery](https://github.com/CadQuery/cadquery) into FreeCAD as native,
parametric document objects. Write or edit a Python model, save it, and watch
FreeCAD recompute—without loading a second, binary-incompatible OCCT stack into
FreeCAD's process.

This is the first tagged public release. Version 0.2 is a **functional alpha**:
the core workflow works end to end and is covered by real FreeCAD integration
tests, but we still expect rough edges and want feedback from early users before
submitting it to the FreeCAD Addon Index.

## Highlights

### Python models become real FreeCAD objects

Every script creates a `Part::FeaturePython` object in the active document. Its
shape saves in `.FCStd`, recomputes, accepts expressions and spreadsheet links,
and can feed downstream TechDraw, FEM, CAM, and Assembly workflows. This is not
a viewer-only preview.

### build123d and CadQuery, safely isolated

Code Workbench runs build123d, CadQuery, OCP, and their Python dependencies in a
separate managed kernel. Geometry crosses the process boundary as serialized
BREP plus metadata, avoiding OCCT symbol conflicts with FreeCAD.

The first setup explains exactly what will be downloaded and where the managed
environment will live. Nothing is provisioned until you approve it.

### A focused editor inside FreeCAD

The embedded editor is built for the tight edit → recompute → inspect loop:

- Python syntax highlighting, line numbers, and auto-indent
- Live completions and call signatures from the kernel environment
- Autosave and recompute after a configurable idle delay
- `Ctrl+Enter` to save and run immediately
- Inline runtime diagnostics with gutter markers, underlines, and tracebacks
- Last-valid-model behavior when the current edit fails

### Or keep your existing editor

Every Script object remains file-backed. Save from VS Code, Neovim, PyCharm, or
any other editor and FreeCAD hot-reloads the model. The `show()` and
`show_object()` APIs are compatible with
[ocp-vscode](https://github.com/bernhard-42/vscode-ocp-cad-viewer), and Code
Workbench auto-discovers top-level shapes when a script shows nothing explicitly.

### Python parameters become FreeCAD properties

List module-level literals in `PARAMS` and they appear in the FreeCAD property
panel. Code Workbench tracks whether each value follows the source or has been
overridden in FreeCAD, preserves overrides across saves, and provides a one-click
reset to the script defaults.

### Names, colors, preferences, and recovery

- Names, colors, and transparency from `show()` / `show_object()` are applied in
  FreeCAD while respecting user renames.
- Package pins, autosave, debounce timing, run timeout, kernel startup, and the
  managed-environment location are configurable.
- A timed-out or crashed kernel is stopped and restarted cleanly on the next run.
- New workbench and command icons make the full workflow easy to scan.

## Install

Code Workbench is not in FreeCAD's Addon Manager yet. For this alpha, clone it
into your FreeCAD user `Mod` directory:

```console
cd /path/to/FreeCAD/Mod
git clone --branch v0.2.0 --depth 1 https://github.com/jokroese/freecad-code-workbench.git
```

Restart FreeCAD, select the **Code** workbench, and approve the first-run kernel
setup. Provisioning can take a few minutes; progress appears in
**View → Panels → Report view**.

Requirements and platform-specific paths are in the
[installation guide](https://github.com/jokroese/freecad-code-workbench#install).

## Compatibility and testing

- FreeCAD 1.0 or later
- Full headless end-to-end CI on FreeCAD 1.0 and 1.1.3
- build123d 0.11.1 and CadQuery 2.8.0 by default
- Managed Python 3.12 with `uv`, or a compatible system Python 3.10+ fallback
- Core tests on Python 3.11 and 3.12
- Linux covered by full automated CI; macOS exercised during development
- Windows paths are implemented, but Windows does not yet have automated CI

The end-to-end test follows the real path: script → managed kernel → BREP →
native FreeCAD object → parameter and recompute behavior.

## Known limitations

- Multiple shown objects currently become one compound rather than a preserved
  assembly hierarchy.
- FreeCAD's synchronous recompute means a legitimate long-running model can
  block the UI until it completes or reaches the configured timeout.
- Kernel requests are serialized, so editor completions wait behind a running
  script.
- BREP data currently travels as base64 inside JSON; very large assemblies may
  eventually require a binary transport.
- Windows needs more field testing.

## Security

Code Workbench executes user-selected Python with your user privileges, just like
a FreeCAD macro. Only open scripts and documents from sources you trust. The
kernel listens on loopback and requires a per-process random token; first-run
downloads require explicit consent.

Please report security issues privately as described in the
[security policy](https://github.com/jokroese/freecad-code-workbench/security/policy).

## Early testers wanted

If you try 0.2.0, please
[open an issue](https://github.com/jokroese/freecad-code-workbench/issues) and tell
us:

1. Your operating system and FreeCAD version
2. Whether you used build123d, CadQuery, or both
3. Whether first-run provisioning completed successfully
4. Whether parameters, hot reload, save/reopen, and diagnostics behaved as expected

Reports of successful installations are useful too—especially on Windows and on
different FreeCAD distributions.

## Next

The immediate goal is to harden installation across platforms, respond to public
alpha feedback, and submit Code Workbench for FreeCAD Addon Manager distribution.
Beyond that, Phase 3 targets preserved assembly hierarchies, bidirectional code/3D
selection, subshape provenance, and more stable downstream references.

Thank you for trying an early release and helping make Python-first CAD feel native
inside FreeCAD.
